# MAK Marketplace

MAK Marketplace is the Heicode marketplace for skills and tools. You can browse and acquire **Skills** and **MCP tools** published by Heicode and third-party publishers, then bind them to a Sub Agent. You can also publish your own skills and tools as a publisher and earn revenue.

*The capabilities described here ship with the first MAK Marketplace release, available from August 2026.*

## What the marketplace offers

The marketplace currently supports two product kinds:

| Kind | Description | Delivery |
|---|---|---|
| **Skill** | A packaged capability, such as code review or documentation generation | Inline delivery (`inline_skill`) — the skill content ships with the entitlement manifest |
| **MCP** | An external tool integration following the MCP protocol, such as code hosting or search tools | Declarative delivery — only the capability claim is delivered, never credentials |

*Note: Publishing and trading Agent templates is not yet available. This release supports Skill and MCP products only.*

## From purchase to taking effect in an Agent

A purchased product does not appear in your Agent automatically. It travels through a fixed delivery chain. Understanding this chain helps you diagnose "I bought it but the Agent can't use it":

1. **Checkout grants an entitlement** — after checkout, the marketplace creates an active entitlement for the buyer.
2. **Capability claim is delivered** — the marketplace exposes a catalog entry for that entitlement using stable governance identifiers such as `skill__code-review` or `mcp__github`.
3. **Manager imports and filters by policy** — Manager imports the entry into the organization's tool catalog and applies the organization's allow/deny policy. Entries denied by policy are not delivered onward.
4. **Delivered with the deployment** — when Manager sends the deployment payload to Agent Management, it includes the policy-approved skills and tools.
5. **Runtime injection and reporting** — Agent Management injects the configuration into the runtime. The Sub Agent health response reports which items loaded, plus structured reasons for any load failure.

In other words: **purchasing completes only step one. Whether a capability takes effect also depends on your organization's policy configuration.** If a purchased capability does not appear in your Agent, check the organization's tool catalog policy first.

## Free versus paid products

| Pricing | Checkout behavior |
|---|---|
| **Free** | The entitlement is granted immediately at checkout, with no payment flow |
| **Paid** | Checkout creates a pending order; the entitlement is granted after the payment provider confirms payment |

Payment results for paid orders are confirmed by provider webhooks. Webhooks are verified and idempotent, so a given order grants **exactly one entitlement** — repeated webhook calls never grant duplicates.

## Credentials for MCP products

MCP product deliveries **never contain organization credentials**.

When you purchase an MCP tool, you receive its capability claim and integration configuration. The credentials the tool needs to reach the external service (such as an access token) must be **bound separately by an organization administrator**. An MCP tool without bound credentials reports a load failure after runtime injection rather than silently proceeding with empty credentials.

## Library and entitlements

Purchase records and usable capabilities live in two separate places:

- **Orders** — transaction records and payment status, with per-order detail.
- **Library** — the list of entitlements you hold, meaning the skills and tools you can currently bind to an Agent.

Entitlements and orders are distinct concepts: an order records *what you bought*, an entitlement records *what you can use now*. Refunds and delistings affect entitlement state without deleting historical orders.

## Becoming a publisher

Publishers can list their own Skill and MCP products. Listings go through review, and move through the following states:

| Status | Meaning |
|---|---|
| **draft** | Created but not submitted for review; visible only to the publisher |
| **pending** | Submitted and awaiting the platform's review decision |
| **published** | Approved, publicly visible in the marketplace, and available for purchase |

After submitting for review, wait for the review decision. A listing is not publicly visible while under review.

Publishers can review revenue and settlement in the personal center.

## Personal and enterprise centers

The marketplace provides two management entry points:

- **Personal center** — account, assets, entitlements, favorites, keys, orders, publishing, and revenue.
- **Enterprise center** — the organization-facing entry point for managing purchases and authorization across the organization.

## FAQ

**I bought a skill, but it does not take effect in my Sub Agent.**

Work through the five-step chain in "From purchase to taking effect in an Agent" above. The most common cause is that the organization's tool catalog policy does not allow the entry.

**An MCP tool reports a load failure.**

First confirm that an organization administrator has bound credentials for that tool. Marketplace delivery excludes credentials by design — this is a security boundary, not a defect.

**Can a single order be charged twice or grant duplicate entitlements?**

No. Payment webhooks are idempotent, and a given order grants exactly one entitlement.

**Can I publish Agent templates?**

Not in this release. The marketplace supports Skill and MCP products only.
