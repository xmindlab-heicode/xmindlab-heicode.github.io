# MAK 市场说明

MAK 市场（HeiCode Market）用于发现、获取和交付可复用的 AI 能力。市场负责商品、订单、权益和余额账本；HeiCode Manager（HM）负责身份、组织治理、审批和部署；Agent Management（AM）与 Swarm 负责实际安装、加载、调用和运行状态。

本文按 **2026 年 8 月 5 日**的实现状态编写。页面显示与本文不一致时，以当前账号实际可见入口和服务端返回状态为准。

## 当前开放范围

| 能力 | 当前状态 | 说明 |
|---|---|---|
| 浏览、搜索和筛选 Skill / MCP | 可用 | 匿名用户可以浏览已发布目录和详情 |
| HM 登录 | 可用 | 获取、购买和工作台操作必须使用 HM 登录态 |
| 免费能力获取 | 可用 | 成功后生成订单和有效权益，不需要外部支付 |
| 余额购买 | 受控 Beta | 已有余额可原子扣款并生成账本、订单和权益；正式充值渠道尚未开放 |
| Skill 部署 | 受控 Beta | 已接入权益、治理、部署和 runtime dispatch；仍应以目标实例的 `running` 与加载状态为验收依据 |
| 无凭据 MCP | 受控 Beta | 组织绑定与 AM 安全物化组件已提供；正式跨仓 E2E 验收完成前不承诺所有目标均可运行 |
| 带凭据 MCP | 暂未开放 | 等待短期凭据租约与 runtime secret alias 完整闭环，当前必须 fail-closed |
| 真实支付、退款与拒付 | 暂未开放 | 余额切片不等于真实支付系统 |

| 发布者收益与提现 | 暂未开放 | 结算、分成和对账未完成，不展示可提现收益 |
| Agent 模板交易 | 暂未开放 | 当前市场商品范围仅为 Skill 和 MCP |

## 能力类型

| 类型 | 用途 | 交付方式 |
|---|---|---|
| **Skill（技能）** | 复用任务方法、知识和工作流，例如代码评审规范、测试策略和文档生成流程 | 经授权后交付固定摘要的技能内容，由 runtime 加载 |
| **MCP（工具）** | 让 Agent 调用搜索、数据库、浏览器、知识库或企业服务 | 市场只交付无密能力声明；组织连接配置与凭据由 HM 单独治理 |

MCP 商品不会把令牌、密码或客户连接配置放进公开详情、权益清单或普通部署载荷。需要凭据但尚未完成安全绑定和短期租约的 MCP 会停在 `binding_required`，不会降级为明文或人工预置。

## 登录与账号类型

市场不维护第二套账号系统。点击右上角登录后，浏览器会跳转到 HM 完成认证，再返回市场。不要把 HM token 放进 URL 或手工粘贴给市场。

个人用户与企业用户由 HM 会话返回的身份和组织关系决定：

- **个人账号**可以为自己获取能力，查看个人订单、权益与余额账本。
- **企业账号**可以在个人和组织购买主体之间选择；组织购买与部署仍会由服务端重新校验成员关系和治理权限。
- 页面选择“组织”不会自动授予管理员权限，也不能绕过组织 allow/deny、审批或连接器绑定。

如果登录后账号类型或组织不正确，请先在 HM 检查当前账号的组织关系，不要通过修改前端参数绕过。

## 获取免费能力

1. 打开 [MAK 市场](https://marketplace.heicode.cc/)，使用搜索、类型或标签找到能力。
2. 进入能力详情，检查类型、版本、风险、治理键、支持的 runtime、交付方式和审批要求。
3. 点击 **登录后获取**，在 HM 完成登录并返回市场。
4. 企业账号选择购买主体：**个人**或**组织**。
5. 免费 SKU 显示为 **免费 · 立即获取**。点击后等待服务端创建订单和权益。
6. 页面跳转到 **已购与授权**，确认权益状态为 `active`。

重复提交使用幂等键，同一次获取不会重复发放权益。订单记录“发生过什么交易”，权益记录“当前是否可以使用”，两者不是同一个状态。

## 使用余额购买

余额购买只适用于账号或组织已有可用余额的场景：

1. 在详情页选择付费 SKU 和购买主体。
2. 点击价格对应的 **立即获取**。
3. 服务端在同一事务中完成余额校验、扣款、不可变账本记录、订单支付状态和一份权益发放。
4. 到 **余额与账本**检查余额变化，到 **订单**检查订单，到 **已购与授权**检查权益。

当前没有面向用户开放的真实充值、银行卡或第三方支付入口，也没有完整退款/拒付流程。测试入金端点在生产环境默认关闭，不属于产品充值功能。

## 部署到 Sub Agent 或 Swarm

获得有效权益后，在能力详情页执行：

1. 点击 **部署能力**。
2. 选择 **Sub Agent（单 Agent）**或**蜂群（Swarm）**。
3. 确认 HM 组织 ID，并填写真实的 Sub Agent ID 或 Swarm 目标 ID。
4. 检查治理键、交付方式和权益摘要。
5. 点击 **创建 Sub Agent（单 Agent）部署**或**创建蜂群（Swarm）部署**。
6. 根据返回状态继续处理，不能把“已创建部署”当成“已加载完成”。

部署链路如下：

```text
订单/免费获取
  -> Marketplace 权益与 Capability Claim
  -> HM 重新校验权益、组织权限与治理策略
  -> HM 创建 Deployment 并派发 runtime adapter
  -> AM 或 Swarm 安装并加载能力
  -> runtime 回传 running 或 failed
  -> 停用/撤回后禁止再次调用
```

### 部署状态

| 状态 | 含义 | 处理方式 |
|---|---|---|
| `binding_required` | MCP 需要组织连接器绑定或安全凭据链路尚未满足 | 由组织管理员完成绑定；带凭据 MCP 当前不可继续 |
| `approval_required` | 已创建记录，等待组织审批，尚未调用 runtime | 等待有权限的管理员审批 |
| `ready` | 已通过当前治理检查，但仍在等待 runtime adapter 派发 | 继续等待，不要宣称已运行 |
| `dispatching` | HM 正在向 AM 或 Swarm 派发 | 查看部署事件，避免重复创建 |
| `running` | runtime 已确认能力处于运行状态 | 再用真实任务验证 Skill 行为或 MCP 工具调用 |
| `failed` | 安装、加载或派发失败 | 查看 `last_error`、runtime health 和审计事件 |
| `revoking` / `revoked` | 正在撤回或已撤回 | 确认目录、安装记录和 runtime capability 均已停用 |

只有 `running` 加上目标 runtime 的已加载状态和真实任务结果，才能证明能力已经可用。

## Skill 与 MCP 的验收差异

### Skill

Skill 加载后，应执行一项能体现该 Skill 约束或流程的真实任务。例如，代码评审 Skill 应对实际 diff 输出风险、回归和缺失测试，而不是只检查健康接口。

验收时确认：

- 权益为 `active`；
- HM 没有因组织策略拒绝治理键；
- Deployment 达到 `running`；
- runtime 报告该 Skill 已加载且没有结构化加载失败；
- 真实任务输出体现 Skill 的规则。

### MCP

MCP 必须执行一次真实工具调用。例如，无凭据 Reader MCP 应读取一个公开 URL 并返回页面内容；仅看到 MCP 名称或配置记录不代表工具可用。

无凭据 MCP 仍需要 active organization binding、治理、审计和 revoke。带凭据 MCP 在短期凭据租约闭环前保持不可部署，不接受把长期 secret 写入 URL、headers、env、Git、日志或 Agent 记忆。

## 个人中心与企业中心

当前正式导航可以出现以下入口，具体取决于 HM 返回的账号类型：

- **我的 Skills / MCP**：查看自己管理的能力资产；完整版本化发布仍在建设。
- **发布能力**：进入发布工作区；发布、审核、下架和紧急撤回以平台实际开放状态为准。
- **我的收藏**：入口可见，但收藏后端尚未完成时页面会明确提示未保存。
- **已购与授权**：查看当前有效权益和部署入口。
- **组织治理**：仅企业账号可见，用于查看组织可用性和部署影响。
- **余额与账本**：查看真实余额与不可变交易记录。
- **订单**：查看交易记录和状态。

“我的收益”“实名与资质”“API 与连接器”“账号设置”等未完成功能不会出现在正式导航中。路由存在不代表产品已经开放。

## 停用与撤回

撤回不是只隐藏市场卡片。完整撤回应同时停止：权益或授权、HM 目录可部署状态、Installation/Deployment，以及 AM/Swarm runtime capability。

操作后至少验证：

1. 权益或组织授权不再允许新部署；
2. HM 目录条目已禁用或不可部署；
3. runtime 不再报告该能力为 loaded；
4. 再次执行原 Skill/MCP 任务会被拒绝，而不是继续使用缓存配置；
5. 审计记录不包含明文凭据。

如果页面没有提供撤回入口，请联系组织管理员或平台支持，不要只删除本地文件来代替服务端撤回。

## 故障排查

### `marketplace origin is not allowed`

这表示 HM 没有允许当前市场来源。请确认从 `https://marketplace.heicode.cc` 打开市场，并由管理员检查 HM 的 Marketplace origin allowlist。不要改用测试域名或在 URL 中携带 token。

### 已获取但“已购与授权”为空

确认当前 HM 登录身份和购买主体是否一致。个人权益不会自动变成组织权益，组织权益也不会显示在另一个组织下。然后检查订单是否成功、权益是否为 `active`。

### 状态停在 `ready`

`ready` 只表示治理检查完成，不表示 runtime 已加载。检查 HM dispatch 事件、adapter 配置、目标 ID 和 AM/Swarm 回调。

### MCP 停在 `binding_required`

检查组织是否有 active connector binding。若 MCP 需要 token、API key 或其他 secret，当前版本会保持 fail-closed，不能通过前端输入明文绕过。

### 状态为 `failed`

记录 Deployment ID、目标类型和目标 ID、治理键、时间、`last_error`、runtime health 中的加载失败原因以及相关审计事件。重试前先修复原因；使用同一幂等操作时不要反复创建重复部署。

## 安全与数据边界

- Marketplace 独占写入 Listing、SKU、Order、Payment、Entitlement 和 Ledger。
- HM 独占写入组织治理、Installation、Deployment、审批和部署审计。
- AM/Swarm 独占写入实际安装、加载、调用和 RuntimeHealth。
- Web 只消费状态，不是任何商业或运行时数据的真源。
- Capability Claim 不包含 Skill 正文、MCP 凭据、客户连接地址、支付数据或用户 token。
- MCP 长期凭据只能保存在密钥保管器中并以 `secret_ref` 引用；普通响应、日志和审计不得回显明文。
- 购买不等于授权，授权不等于部署，`ready` 不等于运行。
