# PRD Reference Template

> Filling this in and freezing the baseline at the end = project initiation complete; only then should you let Agents start writing code.
>
> Most items are simple checkboxes (`[x]`); only three places need you to write a longer passage.
>
> Put it at the project root and name it `PRD.md`; when requirements change later, edit this same file.

## Step 0 · Describe What You Want to Build, in One Long Passage

> This is the most important passage — don't skip it. No bullet points or jargon needed; write it as if explaining to a person.
>
> Try to cover: what you want to build → who will use it → how they solve this today → how you want them to do it instead → what result would satisfy you → what you explicitly don't want.

(Write here. Any length is fine.)

## Change Control · The 50% Red Line

Measured cumulatively, not per change:

```text
Feature drift rate = (added + removed + substantially changed P0 items) / baseline P0 items
Hard metric drift  = |current value - baseline value| / baseline value   (calculated separately for duration and budget)
Total drift rate   = the maximum of the above
```

"Substantially changed" = the definition of done changed, or the implementation approach was replaced wholesale. Copy edits and style tweaks don't count.

| Total drift rate | Verdict | What to do |
|---|---|---|
| &lt; 20% | Normal change | Update the PRD and record it in the table below |
| 20% ~ 50% | Major change | Stop the affected development, re-review, update the baseline, and write down why the original judgment was off |
| **&gt; 50%** | **Project not viable** | **Stop execution**, return to Part 1 to re-research and re-initiate, and produce v2.0. Do not keep patching the original PRD |

> Exceeding 50% means the problem definition or solution judgment made at initiation is no longer valid; continuing means adding investment on top of a wrong premise.
